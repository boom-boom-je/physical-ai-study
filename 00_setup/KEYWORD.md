면담이나 복습 때 가장 먼저 보는 정리입니다. 자세한 과정은 [`notes.md`](notes.md)(Q&A), 과제와 답은 [`README.md`](README.md)에 있습니다.

## 1. 강화학습 기본 용어

| 용어 | 정의 | S0에서의 예 |
|---|---|---|
| 환경 (environment) | 에이전트가 행동하면 다음 상황과 보상을 돌려주는 세계 | `HalfCheetah-v5`: MuJoCo 위의 치타 로봇 |
| 에이전트 (agent) | 환경 안에서 관측을 보고 행동을 고르는 주체 | 치타를 조종하는 프로그램 |
| 정책 (policy) | 관측을 받아 행동을 내놓는 규칙(함수). 강화학습은 이 정책을 학습으로 만든다. S2에서 확률로 확장한다 | 아직 없음. 무작위 행동으로 대신했다 |
| 관측 (observation) | 정책이 매 스텝 받는 현재 상태의 숫자 보고서 | 숫자 17개: 몸통 높이·기울기, 관절 각도, 속도·각속도 |
| 행동 (action) | 정책이 매 스텝 환경에 내보내는 값 | 관절 6개의 토크, 각 -1~1 |
| 보상 (reward) | 행동 한 번에 대한 점수. 학습은 보상의 합을 키우는 방향으로 진행된다 | 앞으로 간 속도 − 힘을 쓴 비용 |
| 스텝 (step) | 행동 1번 → 시뮬레이터가 조금 진행 → 결과를 받는 한 번의 주고받기 | 0.05초 |
| 에피소드 (episode) | `reset()`부터 끝날 때까지 이어진 스텝의 묶음 | 1000스텝 = 50초 |
| 에피소드 보상 | 한 에피소드 동안 받은 보상의 합. 정책끼리 비교하는 점수 | 랜덤 에이전트 1000스텝 약 -200~-300 |
| `terminated` | 환경 자체의 규칙(실패·성공)으로 끝남. 더 진행할 상태가 없다 | HalfCheetah는 항상 False (넘어져도 끝나지 않음) |
| `truncated` | 시간 제한 같은 바깥 사정으로 잘림. 더 갈 수 있었지만 기록이 멈춘 것 | 1000번째 스텝에서 True |
| 랜덤 에이전트 | 정책 대신 행동을 무작위로 뽑는 에이전트 | `env.action_space.sample()` |
| 기준선 (baseline) | 학습한 정책이 의미 있는지 비교할 바닥 점수 | 300스텝 약 -60 (시드 0에서 -103.8) |
| 시드 (seed) | 무작위 값의 순서를 고정하는 번호. 같은 시드면 같은 결과가 나온다(재현성) | `env.reset(seed=0)`, `env.action_space.seed(0)` |

## 2. HalfCheetah 한눈에

- **관측 17개** = 위치·각도 8개 + 속도·각속도 9개 = 관절 6개 × (각도, 각속도) 12개 + 몸통 5개

  | Num | 내용 | Num | 내용 |
  |---|---|---|---|
  | 0 | 몸통 높이 (처음 높이 기준 변화량, m) | 8 | 몸통 앞뒤 속도 (m/s, +면 앞으로) |
  | 1 | 몸통 기울기 (rad) | 9 | 몸통 위아래 속도 (m/s) |
  | 2~4 | 뒷다리 허벅지·정강이·발 각도 | 10 | 몸통 기울기 각속도 (rad/s) |
  | 5~7 | 앞다리 허벅지·정강이·발 각도 | 11~16 | 관절 6개 각속도 (rad/s) |

- **관측에 없는 것:** 몸통의 앞뒤 위치 x. 트랙 어디서든 같은 방식으로 달려야 하고(위치와 무관한 행동), x는 달릴수록 계속 커져서 학습 때 보지 못한 값이 되기 때문이다. 대신 앞뒤 **속도**(8번)는 들어 있다.
- **행동 6개:** 0~2 뒷다리 허벅지·정강이·발, 3~5 앞다리 허벅지·정강이·발의 토크. 행동 k번은 관측 (k+2)번 각도, (k+11)번 각속도와 짝이다.
- **보상 식:** `reward = 1.0 × 앞뒤 속도 − 0.1 × (행동 6개 제곱의 합)`
  - 무작위 행동은 제곱의 평균이 1/3이라 `ctrl_cost`가 스텝당 0.1 × 6 × 1/3 = **0.2**다. 300스텝이면 약 60이 빠진다.
  - `forward_reward`의 합 = **이동 거리(m) × 20**이다 (한 스텝이 0.05초라서).
- **시간:** 한 스텝 0.05초, 1000스텝(50초)에서 시간 제한으로 잘린다. 실제 속도로 재생하려면 초당 20장.
- **2차원(평면) 모델:** 앞뒤(x)와 위아래(z)로만 움직이고 좌우는 없다.
- **몸통에는 모터가 없다.** 다리로 바닥을 밀어서 간접적으로만 움직인다.

## 3. Gymnasium·MuJoCo 용어

| 용어 | 정의 |
|---|---|
| Gymnasium | 강화학습 환경을 같은 사용법(`reset`, `step`)으로 쓰게 해 주는 파이썬 라이브러리 |
| MuJoCo | 관절·접촉·마찰을 계산하는 물리 시뮬레이터 |
| 래퍼 (wrapper) | 환경을 감싸 기능을 덧붙이는 껍데기. `TimeLimit`은 1000스텝 제한, `OrderEnforcing`은 `reset()` 전에 `step()`·`render()`를 부르면 막는다 |
| `env.unwrapped` | 래퍼를 벗긴 원래 환경. 물리 값을 바꿀 때 여기로 들어간다 |
| `model` / `data` | `model` = 로봇의 설계도(질량·마찰 등, 고정), `data` = 지금 상태(위치·속도, 매 스텝 바뀜) |
| `qpos` / `qvel` | 관절 위치 9개 / 관절 속도 9개. 관측 = `qpos`에서 x를 뺀 8개 + `qvel` 9개 |
| body | 하나로 움직이는 몸 조각 (몸통, 허벅지, 정강이, 발) |
| `body_mass` | body별 질량 배열(kg, 8칸). 0번 world = 0, 몸통 6.25(약 45%), 합계 14 |
| world | 0번 body. 움직이지 않는 세상과 바닥이라 질량이 의미가 없어 0이다. 몸통이 여기에 관절로 붙어 있다 |
| 관절 종류 | `slide` = 직선으로 미끄러짐(`rootx`, `rootz`), `hinge` = 회전(`rooty`, 다리 6개) |
| actuator (모터) | 토크를 거는 장치. 다리 관절 6개에만 있다 |
| `settotalmass` | 모델 파일이 질량 합을 14kg으로 맞추는 옛 설정. 실행할 때 나오는 경고는 "앞으로 없어질 예정"이라는 안내다 |
| 관측의 기준점 | 문서에는 "front tip(앞 끝)"이라고 쓰여 있지만 실제로는 **몸통 중심**이다 |
| `render_mode` | `"human"` = 창에 보여 주기만 함, `"rgb_array"` = 화면을 숫자 배열로 돌려줌 |
| `track` 카메라 | 치타를 따라가는 카메라 (`camera_name="track"`). Gymnasium 1.4의 기본 카메라는 시작 위치에 고정돼 있다 |

## 4. 물리

| 개념 | 정의·식 | 쓰이는 곳 |
|---|---|---|
| 토크 (torque) | 관절을 돌리는 힘 (N·m). 부호가 회전 방향 | 행동 |
| τ = Iα | 토크 = 관성 × 각가속도 (F = ma의 회전 버전). 토크가 각속도를 바꾸고, 그게 쌓여 각도가 바뀐다 | 행동 → 관측 11~16 → 관측 2~7 |
| 라디안 (rad) | 각도 단위. π rad = 180°, 1 rad ≈ 57° | 관측의 각도 |
| 속도·각속도 | 위치·각도가 1초에 변하는 양 = 시간에 대한 미분 | 관측 8~16 |
| a = F/m | 같은 힘이면 무거울수록 덜 가속된다. 질량을 늘리면 움직임이 둔해진다 | `body_mass` 1.5배 |
| 관성 (`body_inertia`) | 회전시키기 어려운 정도. 질량만 바꾸면 그대로 남는다 | Project 1 설계에서 정할 것 |
| 마찰 | 바닥을 누르는 힘이 클수록 커진다 | Project 1의 `geom_friction` |

## 5. 파이썬·NumPy·도구

| 용어 | 정의 |
|---|---|
| NumPy 배열 (`ndarray`) | 숫자 표. 관측·행동·그림이 모두 NumPy 배열이다 |
| 처음 받은 배열 확인 4가지 | 종류(`type`), 모양(`shape`), 자료형(`dtype`), 범위(`min`·`max`) |
| `shape` | 각 차원의 크기. 관측 `(17,)`, 그림 `(320, 320, 3)` |
| `uint8` | 0~255 정수. 그림의 픽셀 값 |
| 스칼라·벡터·"몇 차원" | 숫자 하나 = 스칼라, 숫자 여러 개 = 벡터. 관측·행동에서 "몇 차원"은 **숫자 개수**(17, 6)다 |
| 그림 = 배열 | (세로, 가로, 색 3개) 모양의 `uint8` 배열. 픽셀마다 빨강·초록·파랑 세기 |
| `for` / `while` | 횟수가 정해지면 `for`, 끝날 조건만 있으면 `while` |
| `range(n)` | 0부터 n−1까지. 마지막 `i`는 n−1이고, 반복 횟수는 n이다 |
| 리스트 | 값을 순서대로 담는 상자. `append`(맨 뒤에 넣기), `len`(개수), `[-1]`(마지막 항목) |
| 다시 대입 | 변수는 저절로 바뀌지 않는다. `=`로 다시 넣어야 새 값이 된다 |
| `.copy()` | 진짜 복사본을 만든다. `b = a`는 같은 상자에 이름표만 하나 더 붙이는 것이다 |
| GIF | 그림 여러 장 + 장당 시간(`duration`, 밀리초) + 반복(`loop=0`). 256색만 쓰고 압축해서 메모리(207MB)보다 훨씬 작다(3~5MB) |
| `imageio.mimsave` | 여러 그림을 한 파일로 저장 (`mimread`는 읽기) |
| Traceback 읽기 | 마지막 줄 = **무엇이** 잘못됐나, 내 파일 이름이 나오는 줄 = **어디서**. 라이브러리 줄은 건너뛴다 |
| 대화형 모드 | `.venv\Scripts\python.exe`로 한 줄씩 실행하며 탐색. `for`문은 `...` 다음 빈 줄에서 Enter |

## 6. 헷갈리기 쉬운 짝

| 짝 | 차이 |
|---|---|
| `terminated` ↔ `truncated` | 환경 규칙으로 끝남 ↔ 시간 제한으로 잘림. 잘린 경우는 "그 뒤에도 보상이 더 있었다"고 계산해야 한다 (S3) |
| 벡터의 차원 ↔ 공간의 차원 | 관측 17차원(숫자 개수) ↔ HalfCheetah는 2차원 평면 모델(앞뒤·위아래) |
| 몸 기준 속도 ↔ 바닥 기준 속도 | 관측 8번은 **바닥 기준** 몸통 속도다. -0.5면 몸통이 뒤로 0.5m/s로 밀리는 중이다 |
| `seed()` ↔ `sample()` | 무작위 순서 고정(반복문 전에 한 번) ↔ 행동 하나 뽑기(매 스텝) |
| 마지막 `i` ↔ 반복 횟수 | `range(300)`의 마지막 `i`는 299, 반복은 300번 |
| 메모리 크기 ↔ 파일 크기 | 실행 중 RAM의 그림 300장은 207MB ↔ 압축한 GIF 파일은 3~5MB |
| 실행마다 점수가 다른 이유 | 이전 실행과 이어져서가 아니라, 시드를 정하지 않아 시작 자세와 무작위 행동이 매번 달라서다 |

## 8. 면담 30초 답변

**관측과 행동은?**
> "관측은 숫자 17개입니다. 몸통의 높이·기울기와 관절 6개의 각도 8개, 그리고 그 값들의 속도·각속도 9개입니다. 행동은 관절 6개에 거는 토크로, -1에서 1 사이의 연속값입니다. 앞뒤 위치는 트랙 어디서든 같은 방식으로 달려야 해서 뺐고, 대신 앞으로 가는 속도는 관측에 들어 있습니다."

**에피소드는 어떻게 끝나고, 랜덤 에이전트 점수는 왜 그 값인가?**
> "HalfCheetah에는 넘어지면 끝나는 규칙이 없어서 `terminated`는 항상 False이고, 1000스텝(50초)이 되면 시간 제한으로 `truncated`가 됩니다. 보상은 앞으로 가는 속도 × 1.0에서 행동 제곱합 × 0.1을 뺀 값입니다. 무작위 행동은 제곱의 평균이 1/3이라 `ctrl_cost`가 스텝당 0.2, 300스텝이면 약 60입니다. 무작위로는 앞으로 거의 못 가서 `forward_reward`는 0 근처이므로, -60은 거의 전부 힘을 쓴 비용입니다."

**랜덤 에이전트는 왜 돌렸고, 질량을 바꾸면 무엇이 달라지며, Project 1은 무엇을 보려는가?**
> "랜덤 에이전트는 환경이 제대로 동작하는지 확인하고, 학습한 정책과 비교할 바닥 점수(기준선)를 얻으려고 돌립니다. `body_mass`를 1.5배로 늘리면 같은 토크로 더 무거운 몸을 움직여야 해서 가속이 느려지고 움직임이 둔해집니다. 바닥을 누르는 힘과 마찰도 커져 같은 행동의 결과가 달라집니다. Project 1에서는 기본 질량으로 학습한 정책을 질량·마찰이 바뀐 환경에서 평가해 성능이 얼마나 무너지는지 재고, 도메인 랜덤화가 이를 얼마나 막는지 봅니다. 시뮬레이터와 현실의 물리 값이 달라서 생기는 sim-to-real 문제를 작게 재현하는 실험이고, 다음 단계인 Project 2는 그 물리 값을 스스로 추정해 적응하는 것입니다."
