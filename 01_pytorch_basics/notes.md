## 1. 텐서 (수업 1)

### Q1. GPU를 쓰려면 `device = "gpu"`라고 쓰면 안 되나?
- 처음 내 답: `device = "gpu"`로 썼더니 에러가 났고, 예시처럼 `"cuda" if torch.cuda.is_available() else "cpu"`로 쓰면 `cuda`가 나왔다.
- 놓친 점: 장치 이름은 내가 붙이는 게 아니라 **PyTorch가 정해 둔 이름**이다. NVIDIA GPU의 이름은 `"gpu"`가 아니라 `"cuda"`다.
- 정리:
  - 에러는 `device = "gpu"` 줄이 아니라 `.to(device)` 줄에서 난다. 변수에는 아무 글자나 담을 수 있고, PyTorch가 그 이름을 장치로 해석하는 순간 모르는 이름이라 멈춘다. 에러 메시지: `Expected one of cpu, cuda, ..., mps, ... device type at start of device string: gpu`
  - **CUDA**는 NVIDIA GPU로 일반 계산을 하게 해 주는 NVIDIA의 도구 모음이다. PyTorch는 NVIDIA GPU 장치를 이 이름으로 부른다. S0에서 설치한 것이 "CUDA 빌드" PyTorch(`cu126`)였다.
  - `cuda:0`은 0번 GPU라는 뜻이다. GPU가 여러 개면 `cuda:1`, `cuda:2`…가 된다. 이 PC는 RTX 3070 Ti 한 개라 `cuda:0`이다. (Apple 칩 맥북의 GPU는 `"mps"`라고 부른다.)
  - `"cuda" if torch.cuda.is_available() else "cpu"`는 파이썬의 조건 표현식(`A if 조건 else B`)이다. 조건이 참이면 A, 거짓이면 B가 된다. 이렇게 쓰면 GPU가 없는 노트북에서도 같은 코드가 CPU로 돌아간다.
- 확인 방법: `torch.cuda.is_available()` → True, `torch.cuda.get_device_name(0)` → NVIDIA GeForce RTX 3070 Ti, `torch.version.cuda` → 12.6 (2026-11-11)
- 덧붙임: 실습 코드에 `"cuda" if torch.cuda.is_available() else "gpu"`라고 썼다. 이 PC에서는 앞쪽 `"cuda"`가 골라져서 문제가 없지만, GPU가 없는 노트북에서는 `"gpu"`가 골라져 같은 에러가 난다. 뒤쪽은 `"cpu"`여야 한다.

### Q2. `obs * w`는 왜 에러가 나고 `obs @ w`는 되나?
- 처음 내 답: 대화형 모드에서 `(obs * w).shape`를 실행해 에러를 확인했다 (예측대로 에러).
- 정리:
  - `*`는 **원소별 곱**이라 같은 위치의 칸끼리 곱한다. 그래서 두 텐서의 모양이 맞아야 한다. `(4, 17)`과 `(17, 6)`은 뒤쪽 차원끼리 비교하면 17과 6이 달라서 짝을 지을 수 없다.
  - 에러 메시지 `The size of tensor a (17) must match the size of tensor b (6) at non-singleton dimension 1`: "1번 차원(0부터 세니 두 번째 차원)에서 17과 6이 안 맞는다"는 뜻이다.
  - non-singleton은 "크기가 1이 아닌"이라는 뜻이다. 크기가 1인 차원은 상대에 맞춰 늘려 주는 규칙(**브로드캐스팅**)이 있다. 예를 들어 `(4, 6)` + `(6,)`는 `(6,)`를 4줄로 늘려 더해진다. 수업 4의 신경망 층(`x @ W + b`)에서 이 규칙을 쓴다.
  - `@`는 **행렬 곱**이라 규칙이 다르다. (a × b) @ (b × c) = (a × c), 즉 앞 텐서의 마지막 크기와 뒤 텐서의 첫 크기(17 = 17)만 같으면 된다. 결과는 `(4, 6)`.
- 확인 방법: `(obs @ w).shape` → `torch.Size([4, 6])` (2026-11-11)

### Q3. GPU에 있는 텐서와 CPU에 있는 텐서를 곱하면?
- 처음 내 답: `obs`만 GPU로 옮기고 `w`는 CPU에 둔 채 `@`를 실행해 에러를 확인했다 (예측대로 에러).
- 정리:
  - 계산은 **같은 장소(device)에 있는 텐서끼리만** 할 수 있다. GPU 메모리와 CPU 메모리는 서로 다른 곳이라, 한쪽 데이터를 다른 쪽으로 옮겨 와야 계산할 수 있다.
  - 에러 메시지 `Expected all tensors to be on the same device, but got mat2 is on cpu, different from other tensors on cuda:0 (when checking argument in method wrapper_CUDA_mm)`: `mat2`는 행렬 곱의 두 번째 행렬(`w`), `wrapper_CUDA_mm`은 GPU용 행렬 곱 함수다. "두 번째 행렬이 CPU에 있어서 GPU 계산을 못 한다"는 뜻이다.
  - 해결: 둘 다 `.to(device)`로 같은 곳에 옮긴다 (실습 ③). 수업 5의 학습 루프에서 **모델과 데이터를 둘 다 GPU로 옮기는 줄**이 이 이유로 필요하다.
- 확인 방법: `obs_g @ w_g`(둘 다 GPU) → 결과 `(4, 6)`, 장소 `cuda:0` (2026-11-11)

### Q4. `torch.from_numpy`로 바꾼 관측의 자료형은? `.float()`는 왜 붙이나?
- 처음 내 답: `from_numpy` 직후는 `float64`, `.float()`를 붙이면 `float32`로 확인했다.
- 정리:
  - S0의 관측은 NumPy `float64`였고, `torch.from_numpy`는 **자료형을 그대로 가져온다**. 그래서 텐서도 `float64`다.
  - 신경망은 보통 `float32`를 쓴다. 메모리가 절반이고 GPU가 훨씬 빠르게 계산한다. PyTorch의 층(가중치)도 기본이 `float32`라, 자료형이 다르면 섞어서 계산할 때 에러가 난다.
  - 그래서 Gymnasium 관측을 신경망에 넣을 때는 `.float()`로 `float32`로 바꿔 준다. P1에서 쓰는 SB3는 이 변환을 내부에서 알아서 한다.
  - 출력할 때는 **바꾸기 전과 후를 둘 다** 찍어야 차이가 보인다.
- 확인 방법: `cheetah.dtype` → `torch.float64`, `cheetah.float().dtype` → `torch.float32` (2026-11-11)

### Q5. `reshape(-1)`로 사진 배치를 펴면 어떻게 되나?
- 처음 내 답: `(8, 1, 28, 28)`을 `picture.reshape(-1)`로 폈다 → `torch.Size([6272])`
- 놓친 점: `-1` 하나만 쓰면 **배치 차원까지 전부** 한 줄로 펴진다. 8장이 숫자 6272개(= 8 × 784)짜리 긴 줄 하나로 합쳐져서, 어디까지가 1번 사진인지 모양만 보고는 알 수 없다.
- 정리:
  - 배치 차원(첫 번째, 사진 개수)은 지키고 **사진 한 장 안쪽만** 펴야 한다. 결과는 `(8, 784)`여야 한다. 28 × 28 × 1 = 784.
  - `reshape`의 칸 수 = 결과의 차원 수다. `reshape(-1)`은 1차원, `reshape(8, -1)`은 2차원이다. `-1`은 "남은 개수로 알아서"라서, `reshape(8, -1)`이면 6272 ÷ 8 = 784가 자동으로 들어간다.
  - 마지막 배치는 장 수가 적을 수 있다 (예: 데이터 1000장을 64장씩 나누면 마지막은 40장). 그래서 실제 코드에서는 8을 직접 쓰기보다 `x.shape[0]`(이번 배치의 장 수)을 쓴다. 수업 4의 `nn.Flatten()`이 바로 "첫 차원은 두고 나머지를 펴는" 일을 한다.
- 확인 방법: 편 뒤 모양이 `torch.Size([8, 784])`인지 본다. `picture.reshape(8, -1)`로 고친 뒤 `(8, 784)`를 확인했다 (2026-11-11).

## 2. autograd (수업 2)

### Q6. `requires_grad` 없이 만든 텐서로 계산하고 `backward()`하면?
- 처음 내 답: 대화형 모드에서 `x = torch.tensor(2.0)`(추적 표시 없음)으로 계산한 뒤 `backward()`를 불러 에러를 확인했다. `x.grad`는 `None`이었다.
- 정리:
  - 에러 메시지 `element 0 of tensors does not require grad and does not have a grad_fn`: "기울기를 구하라는 표시도 없고, 계산 기록(`grad_fn`)도 없다"는 뜻이다.
  - **`grad_fn`**은 그 텐서를 만든 계산의 기록이다. 추적 표시가 붙은 텐서로 계산하면 결과에 `grad_fn`이 남는다 (예: 곱하면 `MulBackward0`, 합하면 `SumBackward0`). `backward()`는 이 기록을 거꾸로 따라간다. 표시가 없으면 기록이 없어서 출발할 수 없다.
  - 신경망의 가중치에는 처음부터 표시가 붙어 있어서, 직접 `requires_grad=True`를 쓸 일은 많지 않다 (수업 4).
- 확인 방법: `print(y.grad_fn)`. 표시 없는 텐서로 계산한 결과는 `None`이다 (2026-11-11).

### Q7. 결과가 벡터일 때 `backward()`를 부르면?
- 처음 내 답: ③에서 `y_2 = w * x_2`로 만들고, 합은 출력(`print(y_2.sum())`)만 한 뒤 `y_2.backward()`를 벡터에 대고 불렀다.
- 놓친 점: `backward()`는 **숫자 하나(스칼라)**에서만 출발할 수 있다. `y_2`는 숫자 3개짜리 벡터라 `grad can be implicitly created only for scalar outputs` 에러가 났다. 출력에 쓴 `y_2.sum()`은 그때 한 번 계산해서 보여 주고 끝난 값이라, `y_2` 자체는 여전히 벡터다.
- 정리:
  - `backward()`는 합(`.sum()`)이나 평균처럼 **숫자 하나로 만든 결과**에 대고 부른다.
  - 그래서 학습의 손실도 항상 숫자 하나다. 배치 64개의 오차를 평균 내서 하나로 만든다 (수업 5).
- 확인 방법: `(w * x_2).sum()`을 변수에 담아 그 변수에서 `backward()`를 부른다. 고친 뒤 `w.grad` = `[4., 5., 6.]`, 추적하지 않은 `x_2.grad` = `None` (2026-11-11).

### Q8. 같은 결과로 `backward()`를 두 번 부를 수 있나?
- 처음 내 답: ④에서 `y_3.backward()` 뒤 `w.grad.zero_()`를 하고, `y_3`를 다시 계산하지 않은 채 `y_3.backward()`를 한 번 더 불렀다.
- 놓친 점: `backward()`가 끝나면 메모리를 아끼려고 계산 기록이 지워진다. 같은 결과로 다시 부르면 `Trying to backward through the graph a second time` 에러가 난다.
- 정리:
  - 기울기를 다시 구하려면 **계산(순전파)부터 다시** 해서 새 기록을 만든다.
  - 학습 루프가 매 반복마다 "순전파 → 손실 → 역전파"를 처음부터 다시 하는 이유다.
- 확인 방법: y를 다시 계산한 뒤 `backward()`를 부르면 에러 없이 기울기가 구해진다. 고친 ④에서 매번 y를 다시 계산하자 에러 없이 실행됐다 (2026-11-11).

### Q9. ①의 14와 ②의 42는 손으로 어떻게 구하나? autograd는 어떤 방법으로 구하나?
- 처음 내 답: ①은 f'(x) = 3x² + 2에 x = 2를 넣어 14. ②는 (3x + 1)²을 전개한 9x² + 6x + 1을 미분해 18x + 6, x = 2를 넣어 42.
- 보완할 점: 둘 다 맞다. 다만 ②는 **연쇄 법칙**으로도 풀 수 있어야 한다. autograd는 식을 전개하지 않고 이 방법으로 계산하기 때문이다.
- 정리:
  - 연쇄 법칙: z = y², y = 3x + 1 → dz/dx = **dz/dy × dy/dx** = 2y × 3. x = 2면 y = 7이라 2 × 7 × 3 = **42**. 전개한 결과와 같다 (2(3x + 1) × 3 = 18x + 6).
  - `backward()`는 계산 기록을 거꾸로 따라가며 **단계마다의 기울기를 곱한다**. z에서 y로(2y = 14), y에서 x로(× 3) 내려간다.
  - 신경망은 층이 수십 개라 전체 식을 전개할 수 없다. 층마다의 작은 미분을 곱해 내려가는 이 방법이 **역전파**이고, S1 "설명해 보기" 1번(`loss.backward()`를 부르면 무슨 일이 일어나나)의 답이다.
- 확인 방법: `x_1.grad` → `tensor(42.)`

### Q10. ③에서 `w.grad`는 왜 `[4, 5, 6]`인가?
- 처음 내 답: w의 기울기로 x_2가 계산되어 x_2의 배열 `[4, 5, 6]`이 나왔다.
- 보완할 점: 방향은 맞다. 식으로 말하면 더 정확하다.
- 정리:
  - y = w₁·4 + w₂·5 + w₃·6이라 **∂y/∂w₁ = 4, ∂y/∂w₂ = 5, ∂y/∂w₃ = 6**이다. 각 가중치의 기울기는 **그 가중치에 곱해진 입력값**이다.
  - 신경망에서의 뜻: 입력이 큰 연결일수록 그 가중치를 조금만 바꿔도 출력이 크게 변하므로 기울기가 크다. 입력이 0이면 그 가중치의 기울기도 0이라 그 데이터로는 바뀌지 않는다.
  - 추적하지 않은 `x_2`의 `.grad`는 `None`이다. 학습할 대상(가중치)만 추적하고, 데이터는 추적하지 않는다.
- 확인 방법: `w.grad` → `tensor([4., 5., 6.])`, `x_2.grad` → `None`

### Q11. `.grad`는 덮어써지나, 더해지나? 학습 루프에서 기울기를 비우지 않으면?
- 처음 내 답: 기존 기울기에 이번 계산이 누적되어 2 × [4, 5, 6] = [8, 10, 12]가 나왔다. `zero_()` 후에는 누적된 값이 초기화되어 다시 [4, 5, 6]이 나왔다. 학습 루프에서 비우지 않으면 기울기가 계속 누적되어 무한으로 발산할 것 같다.
- 보완할 점: 누적과 초기화 설명은 정확하다. "무한으로 발산"은 그럴 수도 있지만, 실제로는 **제자리에 수렴하지 못하고 계속 흔들리는** 경우도 많다.
- 정리:
  - `backward()`는 `.grad`를 덮어쓰지 않고 **더한다**. 그래서 매 반복마다 비워야 이번 데이터의 기울기만 남는다. 학습 루프의 `optimizer.zero_grad()`가 이 일을 한다 (S1 "설명해 보기" 2번).
  - 비우지 않으면 이번 걸음에 **지난 모든 걸음의 기울기가 섞인다**. 이미 지나온 위치의 방향까지 계속 따라가서 목표를 지나치고 되돌아오기를 반복한다.
  - 실험 ((w − 3)²을 줄이기, 시작 w = 0, 학습률 0.1, 40걸음): 비우면 3.0으로 수렴했다. 비우지 않으면 3을 지나 6까지 갔다가 0 근처로 돌아오기를 계속 반복했다. 학습률이 크거나 신경망이 복잡하면 발산할 수도 있다.
  - 더해지는 성질을 일부러 쓰기도 한다. GPU 메모리가 작을 때 작은 배치 여러 개의 기울기를 모은 뒤 한 번에 업데이트하는 방법이다 (기울기 누적).
- 확인 방법: 두 번째 `backward()` 뒤 `w.grad` → `[8., 10., 12.]`, `zero_()` 후 다시 계산하면 `[4., 5., 6.]` (2026-11-11)

## 3. Dataset·DataLoader (수업 3)

### Q12. 튜토리얼의 `v2.Compose([v2.ToImage(), v2.ToDtype(torch.float32, scale=True)])`는 `ToTensor()`와 같은가?
- 처음 내 답: 수업 설명은 `ToTensor()`였지만, 공식 튜토리얼(Datasets & DataLoaders)을 보고 v2 방식으로 썼다.
- 정리:
  - 새 torchvision이 권장하는 방식이고, 결과는 `ToTensor()`와 같다.
  - `v2.ToImage()`: 사진을 `(1, 28, 28)` 텐서로 바꾼다. 아직 0~255 정수(`uint8`)다.
  - `v2.ToDtype(torch.float32, scale=True)`: `float32`로 바꾸면서 255로 나눠 0~1로 맞춘다. `scale=True`가 이 나누기다.
  - 꺼낸 사진의 종류는 `torch.Tensor`가 아니라 `torchvision.tv_tensors.Image`다. 텐서를 이어받은 종류라 텐서와 똑같이 쓸 수 있고, 출력하면 `Image([...])`로 보인다.
  - 같은 변환을 두 곳에 쓸 때는 `transform = v2.Compose(...)`처럼 변수에 담아 재사용한다. 고칠 때 한 곳만 바꾸면 된다.
- 확인 방법: `type(img)` → `torchvision.tv_tensors._image.Image`, `isinstance(img, torch.Tensor)` → True, 모양 `(1, 28, 28)`, `float32`, 0.0~1.0 (2026-11-12)

### Q13. Dataset에서 꺼낸 한 개는 어떻게 다루나?
- 처음 내 답: `print(training_data[0])`로 통째로 출력했다. 사진 숫자 784개가 110줄 넘게 출력됐다.
- 정리:
  - `data[i]`는 **(사진, 정답) 두 개짜리 묶음(튜플)**이다. `img, label = training_data[0]`처럼 두 변수로 나눠 받는다. S0의 `observation, info = env.reset()`과 같은 문법이다.
  - 큰 배열은 통째로 찍지 말고 확인 4가지(종류·모양·자료형·범위)만 찍는다.
  - 정답 번호를 이름으로 바꾸려면 `training_data.classes[label]`을 쓴다 (0번 사진: 9 → `Ankle boot`).
- 확인 방법: 나눠 받은 뒤 `img.shape`, `label`, `training_data.classes[label]` 출력

### Q14. DataLoader에서 묶음은 어떻게 꺼내고, 묶음 수와 마지막 묶음 크기는 어떻게 확인하나?
- 처음 내 답: ③(묶음 하나 꺼내기)과 ④(묶음 세기)를 어떻게 써야 할지 몰라 비워 두었다.
- 정리:
  - **첫 묶음만:** `next(iter(로더))`. `iter()`는 컨베이어를 켜서 꺼낼 준비를 하고, `next()`는 다음 묶음 하나를 받는다.
  - **전부 차례로:** `for X, y in 로더:` (실제 학습 루프는 이 방식이다)
  - 꺼낸 묶음은 **(사진 묶음, 정답 묶음)** 두 개짜리라, Dataset의 한 개(Q13)처럼 쉼표로 두 변수에 나눠 받는다. 관례상 사진 묶음은 `X`, 정답 묶음은 `y`.
  - `len(로더)`는 사진 장 수가 아니라 **묶음 개수**다.
  - 반복할 때마다 같은 변수에 값을 덮어쓰면, 반복이 끝난 뒤에는 **마지막 값만 남는다** (S0에서 반복 후 `i`를 출력한 것과 같은 원리, S0 Q13). 그래서 `for`문 안에서 `X.shape[0]`을 변수에 담고 반복 뒤에 출력하면 마지막 묶음의 장 수가 나온다.
- 확인 방법: `len(train_dataloader)`, 반복 뒤 마지막 묶음 장 수를 출력해 60000 ÷ 64의 몫·나머지와 비교한다. 실행 결과: 묶음 모양 `X` = `(64, 1, 28, 28)`, `y` = `(64,)`, 마지막 묶음 32장 (2026-11-12).

### Q15. 정답 이름을 `training_data.classes[-1]`로 출력해도 되나?
- 처음 내 답: 0번 사진의 정답 이름을 `training_data.classes[-1]`로 출력했고, `Ankle boot`가 나왔다.
- 놓친 점: `[-1]`은 "리스트의 마지막 이름"이라, **어떤 사진이든 항상** `Ankle boot`가 나온다. 0번 사진의 정답이 마침 마지막 종류(9번)여서 우연히 맞았다.
- 정리:
  - 정답 이름은 **그 사진의 정답 번호로** 꺼내야 한다: `training_data.classes[answer]`.
  - 결과가 맞아 보여도, **다른 예로 한 번 더** 확인하면 우연인지 아닌지 가려진다. 예를 들어 1번 사진(정답 0)에 `[-1]`을 쓰면 `T-shirt/top`이 아니라 `Ankle boot`가 나와서 틀린 게 드러난다.
  - 숫자 하나짜리 텐서는 `tensor(0.)`처럼 출력된다. `.item()`을 붙이면 보통 숫자(`0.0`)가 된다. 수업 5에서 손실 값을 기록할 때 `loss.item()`으로 쓴다.
- 확인 방법: 0~3번 사진의 정답은 9, 0, 0, 3 → 이름은 Ankle boot, T-shirt/top, T-shirt/top, Dress. `classes[-1]`은 네 번 모두 Ankle boot였다 (2026-11-12).

### Q16. `len()`은 무엇에 쓰느냐에 따라 무엇을 세나?
- 처음 내 답: 묶음 개수를 출력하려고 `len(X), len(y)`를 출력했고 `64 64`가 나왔다.
- 놓친 점: `len(X)`는 **한 묶음 안의 사진 장 수**(64)다. 묶음 개수는 DataLoader에 써야 나온다.
- 정리: 같은 `len()`이라도 대상에 따라 세는 것이 다르다.

  | 코드 | 세는 것 | 값 |
  |---|---|---|
  | `len(training_data)` | 데이터 전체의 사진 장 수 | 60000 |
  | `len(train_dataloader)` | 묶음(배치) 개수 = 한 에폭의 반복 횟수 | 938 |
  | `len(X)` (= `X.shape[0]`) | 한 묶음 안의 사진 장 수 | 64 (마지막 묶음은 32) |

  - 60000 = 64 × 937 + 32 → 꽉 찬 묶음 937개 + 32장짜리 1개 = 938개.
- 확인 방법: `len(train_dataloader)`를 출력해 938인지 본다. 고친 뒤 938을 확인했다 (2026-11-12).

### Q17. `X.shape` = `(64, 1, 28, 28)`의 네 숫자와 `y.shape` = `(64,)`는 무엇을 뜻하나? 마지막 묶음은 왜 32장인가?
- 처음 내 답: X의 네 숫자는 한 묶음의 사진 수와 사진의 모양이고, 정답 묶음은 하나의 묶음만 있어서 사진의 수만 보여 준다. 마지막 묶음은 6만 장을 64장씩 938묶음으로 나누고 남은 32장이다.
- 보완할 점:
  - X의 "사진의 모양"을 하나씩 말한다: **64 = 묶음 안의 사진 장 수, 1 = 색 채널 수(흑백), 28 = 세로 픽셀, 28 = 가로 픽셀.** PyTorch 사진은 `(채널, 세로, 가로)` 순서이고, S0의 화면 배열은 `(세로, 가로, 채널)` 순서였다.
  - y가 `(64,)`인 이유는 묶음이 하나여서가 아니라, **사진 한 장의 정답이 숫자 하나(0~9)**이기 때문이다. 사진 64장 → 정답 숫자 64개짜리 벡터다.
  - 묶음 수 계산: 60000 ÷ 64 = **937 … 나머지 32**. 꽉 찬 64장 묶음이 937개이고, 남은 32장이 마지막 한 묶음이 되어 **합계 938개**다. "64장씩 938묶음 + 32장"이면 938 × 64 = 60032로 6만 장을 넘는다.
- 확인 방법: `len(train_dataloader)` → 938, 마지막 묶음 장 수 → 32 (2026-11-12)

### Q18. 튜토리얼의 `NeuralNetwork` 클래스와 `seq_modules`를 둘 다 써야 하나? 클래스의 각 부분은 무슨 뜻인가?
- 처음 내 답: 튜토리얼 "Build the Neural Network"에서 `NeuralNetwork` 클래스(Define the Class)와 `seq_modules = nn.Sequential(flatten, ...)`(Model Layers)를 둘 다 옮겨 썼다. 실행하니 `NameError: name 'flatten' is not defined`가 났다.
- 놓친 점:
  - 튜토리얼의 **Define the Class**가 실제로 쓸 모델이다. 아래 **Model Layers**는 층을 하나씩 떼어 보여 주는 설명용 예시다. `flatten` 변수도 그 설명 앞부분(`flatten = nn.Flatten()`)에서 만든 것이라, 그 줄 없이 `seq_modules`만 옮기면 에러가 난다.
  - 클래스는 **설계도**라서 정의만 하면 모델이 생기지 않는다. `model = NeuralNetwork()`로 실물(인스턴스)을 만들어야 한다. S0에서 `gym.make(...)`로 환경 객체를 만든 것과 같다.
- 정리 (클래스의 각 부분):
  - `class NeuralNetwork(nn.Module)`: `nn.Module`이 가진 기능(가중치 관리, GPU 이동 등)을 이어받은 내 모델의 틀
  - `__init__`: 부품(층)을 만드는 곳. `super().__init__()`은 부모(`nn.Module`)의 준비 작업을 먼저 하는 줄로, 빼면 에러가 난다.
  - `self.flatten`, `self.linear_relu_stack`: 부품을 모델에 붙여 둔다. `self.`로 붙여야 `model.parameters()`가 그 안의 가중치를 찾는다.
  - `forward(self, x)`: 데이터가 지나가는 순서. `model(X)`처럼 부르면 실행된다 (`model.forward(X)`로 직접 부르지 않는다).
  - 모양 변화: `(64, 1, 28, 28)` → Flatten → `(64, 784)` → 층 3개 → `(64, 10)`
- 확인 방법: `model = NeuralNetwork().to(device)` 후 `print(model)`로 구조를 출력한다. 고친 뒤 `model = NeuralNetwork()`, `model.to(device)`로 만들고 구조 출력과 가중치가 `cuda:0`에 있는 것을 확인했다 (2026-11-12).

### Q19. `print(model)`의 `Flatten(start_dim=1, end_dim=-1)`, `bias=True`는 무슨 뜻인가? `model.to(device)`와 텐서의 `.to(device)`는 같은가?
- 정리:
  - `Flatten(start_dim=1, end_dim=-1)`: **1번 차원부터 마지막 차원까지** 편다는 뜻이다. 0번 차원(장 수)은 그대로 둔다. 수업 1의 `reshape(8, -1)`과 같은 일이다 (Q5).
  - `Linear(in_features=784, out_features=512, bias=True)`: 입력 784개 → 출력 512개, `bias=True`는 x @ W **+ b**의 b(더하는 값)가 있다는 뜻이다.
  - **`.to(device)`는 대상에 따라 다르게 동작한다.**
    - 모델: `model.to(device)`는 **모델 자체**를 옮긴다. 다시 대입하지 않아도 된다.
    - 텐서: `X.to(device)`는 GPU에 **복사본을 새로 만들어 돌려줄 뿐**, `X`는 CPU에 그대로 남는다. 그래서 반드시 `X = X.to(device)`처럼 **다시 대입**해야 한다. 빠뜨리면 "장소가 다른 텐서끼리 계산" 에러(Q3)가 난다.
- 확인 방법: `next(model.parameters()).device` → `cuda:0`. 텐서는 `X.to(device)`만 쓰고 `X.device`를 찍으면 여전히 `cpu`다.

### Q20. 모델에는 무엇을 넣고, 출력은 어디에 담나? 정답 `y`도 모델에 넣나?
- 처음 내 답: `X = X.to(device)` 다음에 `X = model(X)`로 출력을 다시 `X`에 담았고, 정답도 `y = model(y)`로 모델에 넣었다. `y = model(y)` 줄에서 `IndexError: Dimension out of range (expected to be in range of [-1, 0], but got 1)`가 났다.
- 놓친 점:
  - 모델에는 **사진(`X`)만** 넣는다. 정답 `y`는 모델의 예측을 **채점할 때만** 쓴다. 학습 루프에서도 정답은 손실을 계산할 때만 쓴다 (수업 5).
  - 에러의 뜻: `y`는 `(64,)`로 차원이 하나(0번)뿐인데, 모델의 첫 층 `Flatten(start_dim=1)`이 1번 차원부터 펴려고 해서 "1번 차원은 없다(가능한 건 -1, 0)"며 멈췄다.
  - 출력을 `X`에 다시 담으면 사진 묶음이 사라지고, 같은 이름이 사진이었다가 점수가 되어 헷갈린다. 출력은 새 이름(`logits`)에 담는다. 반면 `X = X.to(device)`는 같은 사진을 장소만 옮긴 것이라 같은 이름을 써도 된다.
- 정리: 사진 → 모델 → 점수(`logits`, `(64, 10)`) → `argmax(dim=1)` → 예측 번호(`(64,)`) → 정답 `y`와 비교
- 확인 방법: `logits = model(X)`로 고친 뒤 `logits.shape` → `(64, 10)` (2026-11-12)

### Q21. 학습 전 모델의 정확도는 예측할 수 있나?
- 처음 내 답: 학습 전 정확도는 예측할 수 없지 않나?
- 보완할 점: **정확한 값**은 가중치가 무작위로 정해져서 예측할 수 없다. 하지만 **대략 어느 근처인지**는 예측할 수 있다. S0에서 랜덤 에이전트의 점수는 매번 달라도 평균 약 -60이라고 계산한 것과 같다 (S0 Q10).
- 정리:
  - 학습 전 모델의 예측은 정답과 아무 관계가 없다. 종류가 10개이고 FashionMNIST는 종류마다 사진 수가 같아서, 맞힐 확률은 평균 **1/10 = 약 10%**다. 이게 이 문제의 **기준선**이다.
  - 실제로 학습 전 모델은 사진과 상관없이 **거의 한 번호만** 고르는 경우가 많았다 (예측: 4, 8, 8, 8, 8, 8, 8, 8, 4, 8). 그래도 종류가 고르게 섞여 있어서 정확도는 10% 근처가 된다.
- 확인 방법: 이번 묶음 10.9%. 무작위 시작 5번으로 테스트 데이터 전체를 재 보니 8.6%, 9.7%, 3.4%, 10.4%, 11.7%였다 (2026-11-12).

### Q22. 이 모델의 가중치는 몇 개이고, 어디에 가장 많나?
- 처음 내 답: 약 67만 개 (맞음)
- 정리:
  - (784 × 512 + 512) + (512 × 512 + 512) + (512 × 10 + 10) = 401,920 + 262,656 + 5,130 = **669,706**
  - 층마다 (입력 수 × 출력 수)개의 W와 출력 수만큼의 b가 있다.
  - 첫 층(784 → 512)에만 약 60%가 몰려 있다. 입력이 클수록 첫 층이 커진다.
  - 모두 `requires_grad=True`라서 학습할 때 67만 개 전부가 기울기를 받아 바뀐다.
- 확인 방법: `for p in model.parameters(): total += p.numel()` → 669706 (2026-11-12)
